# Momo Blog · 使用与维护

[返回项目介绍](../README.md) · [Railway 部署](../README.md#railway-部署)

## 本地使用

需要 Node.js 24.14–24.x。在 macOS 上可以直接双击 `start-local.command` 启动；也可以在此文件夹打开终端执行：

```sh
npm install
npm run build
npm start
```

打开 **[本地首页](http://127.0.0.1:4318)**。默认仅监听本机，不会自动发布到互联网。

开发时运行 `npm run dev`，前台为 [开发预览](http://127.0.0.1:4317)，后台端口为 4318。

可复制 `.env.example` 为 `.env` 来配置端口和数据目录；`APP_URL` 必须与实际打开的地址一致。示例默认对应正式构建预览的 4318；使用开发前台时改为 `http://127.0.0.1:4317`。同时运行多个副本时，应使用不同端口和 `DATA_DIR`。

## 创建管理员

没有预设邮箱、密码或默认账号。第一次启动后：

1. 打开 [本地管理入口](http://127.0.0.1:4318/login)，线上部署使用你的网站域名加 `/login`；也可以点首页底部「管理」。
2. 从运行网站的机器上读取 `DATA_DIR/setup-token.txt`（默认 `data/setup-token.txt`）。Railway 请在服务的 Console 中读取；按 README 的卷挂载设置，执行 `cat /app/data/setup-token.txt`。若配置了 `SETUP_TOKEN` 环境变量，使用该值。
3. 输入你自己的邮箱和至少 12 位密码，点击「创建并登录」。

令牌在运行服务的机器上生成，线上与本地实例的令牌相互独立；创建管理员后初始化入口自动关闭。账号和会话保存在 SQLite，密码由 Better Auth 哈希保存。此阶段没有邮件服务和密码找回功能。

## 修改首页

登录后点击底部悬浮栏「编辑页面」。管理栏固定悬浮在页面底部，不占用页面排版空间，打开弹窗后仍可操作。标题、简介、页脚寄语可直接修改；每张卡片的「编辑」按钮打开相应内容面板。

- 底部悬浮管理栏的「更换主题」可选择清新绿、卡通粉和午夜紫。点击后立即进入草稿预览，保留已编辑的内容；点击「保存修改」后成为访客也能看到的网站主题，取消则恢复上次保存的样式。三个主题共用所有内容、页面布局和功能，旧网站默认为清新绿。卡通粉使用平滑字体、圆线条猫咪和彩色卡片。
- 进入编辑模式后，「认识我」弹窗中的个人介绍、简介、正文和寄语可直接点击修改，支持换行；点击底部悬浮栏的「保存修改」。简介、个人介绍和寄语与首页共用，「认识我正文」单独保存，可清空。右上方「编辑」仍可打开「个人资料与联系」，其中也可修改正文；旧内容默认保留原先那段介绍。
- 项目、文章、照片、收藏、友链、歌曲可新增、修改、删除，使用上下箭头调整顺序。
- 文字的标题、摘要和封面都可留空。不上传或移除封面后自动使用纯文字布局，列表不显示空白占位图；没有标题时直接显示摘要，摘要留空则取正文开头。首页和文字列表在内容下显示发布时间，详情页保留完整正文与换行。
- 新增文字自动记录当前日期和具体时间（到秒），也可在编辑面板中修改。时间按网站设置的时区显示，修改时区不会改变已经记录的实际时刻。旧文字只有日期时保持原日期，补填时间后才显示具体时刻；时间留空可继续只显示日期。
- 友链入口位于「收集」右侧，独立地址为 `/friends`。进入编辑模式后，点击友链栏目标题右侧的「编辑」，可填写网站名称、简介、网站链接和可选头像；网站链接须以 `https://` 或 `http://` 开头。无头像时显示名称首字，点击卡片会在新标签页打开网站。旧站点没有友链数据时显示空状态。
- 标题右侧的头像可在「个人资料与联系」中上传、替换或移除，保存后生效；卡通粉主题中，图片铺满圆角相框。默认示例为 `assets/profile/avatar-demo.webp`，来源说明见 `assets/profile/README.md`。
- 浏览器标签页图标（favicon）使用已保存的个人头像，保存新头像后自动更新；移除头像并保存后恢复当前主题的猫咪图标。
- 首页照片从相册随机展示，标题直接使用对应照片的标题，在相册中统一管理。
- 顶部地点和时钟卡片的「编辑」打开「地点与时区」。搜索并选择城市会同时设置地点名称、地区标记、时区和天气坐标；名称和地区标记可自行改写，时区可单独选择。也可展开「手动设置天气位置」，填入经纬度并点击「应用天气位置」。搜索依赖 [Open-Meteo 城市搜索](https://open-meteo.com/en/docs/geocoding-api)，数据来自 GeoNames。
- 地点与时区在草稿中可预览，点击底部「保存修改」后持久保存；取消会恢复原设置。旧站点默认使用悉尼，不覆盖已有内容。只改显示名称或时区不会改变天气坐标，请通过选择城市或应用坐标更新天气位置。
- 图片支持 JPEG、PNG、WebP，最大 20 MB。编辑面板按原比例完整预览图片，不裁掉上下或两侧内容；页面卡片仍按各自布局展示。服务端检查实际格式、完整解码并移除照片 EXIF，生成 WebP 和缩略图。暂不接收动画图或超过 4000 万像素的图片。
- 音乐支持 MP3、M4A、WAV，最大 50 MB、30 分钟。服务端校验实际格式、音频信息并进行完整解码；有视频轨道的文件不作为音乐接收。
- 面板里的修改先进入草稿。「返回首页预览」只关闭面板；底部「保存修改」成功后才更新公开内容。
- 「取消」恢复公开内容。保存失败会保留草稿，可重试；离开未保存页面时浏览器会提醒。
- 多窗口保存使用内容版本检查。收到冲突提示时，请先保留自己需要的文字，然后取消并重新编辑最新版本，避免覆盖另一个窗口的修改。

草稿只保存在当前打开的页面，不承诺关闭标签页后恢复。上传但未发布的素材只有管理员可以访问；取消编辑不会自动删除已上传文件，方便后续人工整理备份。

## 访客功能

顶部导航切换首页、项目、文字、相册、收集和友链；五个栏目在导航下方全屏展示，内容滚动时导航保持可见。栏目和项目／文章详情拥有独立地址，支持直接打开、刷新及浏览器前进后退。相册以瀑布流照片墙展示，大幅主图和高低错落的 Bento 卡片自动适配屏幕；点击照片可查看完整大图，支持左右方向键、缩略图和前后按钮，Esc 或「返回照片墙」恢复原来的浏览位置。收集可分类筛选与搜索。切换栏目不中断音乐，页面底部保留播放／暂停。留言表单和素材说明以弹窗显示，Esc 可关闭。

首页照片每次进入首页时从相册随机选择一张，停留期间保持不变；进入或退出编辑模式时保持当前照片，点击照片打开的也是这一张。删除当前展示的照片后，会从剩余照片中重新选择，空相册显示占位。

项目、文字、相册和收集的单条详情页省略栏目大标题、简介与编号，导航下方直接显示返回入口和内容，编辑模式下保留编辑按钮；返回列表或照片墙时恢复栏目标题。相册详情的缩略图切换位于大图与说明下方，横向排列。首页「最近写下的」在三套主题中均自动分配卡片高度，完整显示最近三篇文字，无需内部滚动；较矮卡片会收紧字号、封面和摘要行数，更多文字通过「全部」查看。

音乐卡片底部显示 GitHub、Email、小红书、Bilibili 入口及实时点赞数；社交链接可在「个人资料与联系」中修改。填写 Bilibili 主页链接并保存后，入口会在新标签页打开主页；未填写时提示主页暂未公开。

音乐使用一个音频实例，可播放、暂停、拖动进度、切换歌曲和调整音量。点击音乐卡片右上角的模式图标，依次切换「顺序播放 → 列表循环 → 单曲循环 → 随机播放」，图标随模式变化，鼠标悬停可查看当前模式与下一种模式。喇叭按钮只打开音量滑块，列表按钮单独打开「音乐列表」大窗口。列表窗口展示歌曲、歌手和封面，可选择歌曲、上一首／下一首、播放／暂停、点击切换模式及拖动进度。顺序播放在最后一首结束时停止，列表循环从头继续，单曲循环重复当前歌曲；随机播放避免连续重复同一首，上一首可返回随机播放过的歌曲。切换模式或关闭列表不会打断播放，Esc 可关闭窗口。浏览器记住歌曲、进度、音量与播放模式，刷新后保持暂停。

音乐封面优先显示手动上传的图片，其次自动读取 MP3／M4A 等音频内嵌的封面，无可用封面时显示默认唱片。已上传的旧歌曲也会自动读取；提取结果保存在素材目录，不修改歌曲或公开内容版本。编辑音乐时可上传自定义图片，或点击「恢复自动封面」。

时钟和日历使用站主设置的时区，并自动处理夏令时。天气由服务端按所选城市坐标读取 Open-Meteo，每个位置和时区分别缓存 15 分钟；切换地点不会沿用另一个城市的天气。无可用数据时显示「天气暂不可用」，旧缓存会明确标注。天气联网才能更新。

签到按已保存的网站时区每天每个浏览器一次，今日访客和运行天数也使用同一时区。历史访问和签到保留当时记录的日期，修改时区不回写历史记录。今日访客按签名浏览器 Cookie 去重；累计访问按页面加载计数；运行天数从数据库首次创建的日期算起。管理员登录后的预览及 `/login` 页面不计数。点赞保存在数据库，可取消。清除 Cookie、换浏览器或换设备会成为新的匿名身份；这不是跨设备账号统计。

## 私人留言

点击「聊聊」可填写称呼、可选回复邮箱和留言（最多 2000 字）。留言保存在本站 SQLite 数据库，不公开展示，不会自动发送邮件。未提交内容仅暂存在当前标签页的会话存储，关闭弹窗或刷新后可继续填写；发送失败保留内容，成功后清空。相同提交标识重试不会生成重复留言。

管理员登录后，底部悬浮栏「留言箱」可分页查看、标记已读／未读和删除留言。所有读取和管理接口都校验管理员会话。提交接口校验来源、输入长度，并限制每个 IP 每 15 分钟 10 次请求；提供隐藏字段拦截简单垃圾提交。

## 示例素材

初始文案依据设计稿，文章正文为可替换示例。悉尼主图为 AI 生成示意图，其他照片来自 Unsplash，音乐为已有的原创演示旋律。来源在首页「素材说明」以及 `assets/demo/LICENSE.md`、`assets/demo/photos.json` 和 `assets/demo/SOURCES.md` 中注明。音乐不是设计图中歌曲的商业录音。

实际内容为 HTML 和可编辑数据；没有把设计稿作为整页背景。默认笔记应用示意图由 HTML 绘制，上传项目封面即可替换。

## 数据与备份

- `data/site.db`：公开内容、版本、单管理员账号、会话、签到、访问、点赞及私人留言。
- `data/uploads/`：独立上传原音频、转码图片和缩略图。
- `data/.auth-secret`：本地会话签名密钥。
- `data/setup-token.txt`：一次性管理员初始化令牌。
- `assets/demo/`：首次启动时导入的示例素材，仅数据库为空时初始化。

备份前停止服务，然后复制整个 `data/` 目录。恢复时整体放回；不要只复制 SQLite 主文件而遗漏正在使用的 WAL 文件。`data/`、所有本地环境文件（保留 `.env.example`）、数据库备份、`artifacts/` 内的验收截图和测试产物、依赖及构建结果均已排除在 Git 之外。README 使用的示例截图单独保存在 `docs/images/`。不要把账号数据、令牌和签名密钥公开，也不要用 `git add -f` 强制加入这些文件。

示例初始化只在空数据库中执行。示例种子不会覆盖现有数据库。保留原数据目录更新代码时，个人内容继续保留；Railway 必须将数据目录挂载到持久卷，容器临时文件不会随重新部署保留。更新或迁移前请备份整个数据目录。

首次启动会自动填入初始内容，不需要勾选开关。页面不再显示额外的示例标记，各条内容可以直接编辑或删除；删除并保存后，重启或重新部署不会自动补回。

### Railway 持久化与迁移

使用一个关联到网站服务的 Volume，将挂载路径和 `DATA_DIR` 都设为 `/app/data`，然后部署设置。SQLite 已内置，不需要另建数据库服务。服务器的 `/app/data` 和你电脑上的 `data/` 是两份独立数据，不会自动同步。

在运行实例的 Console 执行 `printenv RAILWAY_VOLUME_MOUNT_PATH`，确认输出 `/app/data`。只填写 `DATA_DIR` 变量不会创建持久卷；卷还必须关联到当前服务及环境。

已有站点补挂卷时：

1. 先保存一份可恢复的数据库快照、完整 `uploads/` 和密钥文件，并下载到容器之外。运行中的 SQLite 应使用一致性备份方式，不能只下载 `site.db` 而忽略 WAL 中的数据。
2. 新卷不会自动复制原容器目录。先安排数据迁移，再让应用使用恢复后的数据库；不要直接覆盖仍被应用打开的数据库文件。
3. 迁移后核对内容版本、素材文件、管理员登录和运行起始日期，再重新部署验证保留情况。持久卷上的数据不应通过 GitHub 仓库传递。

如果已经再次出现初始化页面，先检查是否挂错卷、改了数据路径，或部署到了另一服务／环境。原卷或备份尚在时，应恢复已有数据；若原数据只在已移除的临时容器内且没有备份，无法靠重新初始化找回。

持久化用于跨部署保留数据，备份用于恢复误删或损坏。挂卷后可在服务 **Backups** 中管理手动与定期备份；备份有独立的计费与保留规则，见 [Railway 备份说明](https://docs.railway.com/volumes/backups)。

提交前运行 `npm run check:publish`，检查暂存区里是否意外加入数据库、上传目录、环境配置、密钥或本机个人路径。Git 忽略规则不能移除已经提交到历史里的文件，因此请在首次提交前检查。

## 验证

```sh
npm run typecheck
npm run build
npm test
npm run test:browser
```

接口测试创建独立临时 SQLite 数据库，退出时清理。浏览器验收使用临时账号和独立数据目录，启动本地 4322 端口，结束后清理；不会修改正常预览的数据。

浏览器验收默认使用 macOS Google Chrome；可设置 `CHROME_BIN` 指向其他 Chrome，也可先执行 `npx playwright install chromium` 使用 Playwright 浏览器。截图与验收记录输出到 `artifacts/`。字体优先使用 Google Fonts 的 DM Sans / Space Grotesk，无法联网时使用系统字体。

## 页面与接口

桌面使用三行 Bento，1100px 以下两列、620px 以下单列滚动。卡通粉首页按窗口高度分配三行空间，较矮的桌面窗口使用紧凑字号、内边距和统一的彩色标题栏，保持一屏展示；清新绿和午夜紫保留各自的卡片样式。提供独立栏目、内容详情与三套可切换主题；不包含多人博客管理、全站自由拖拽或自定义主题编辑器。

| 接口                                                  | 用途                                          |
| ----------------------------------------------------- | --------------------------------------------- |
| `GET /api/home`                                       | 公开内容与版本                                |
| `PUT /api/home`                                       | 管理员保存内容，检查版本与素材引用            |
| `POST /api/media?kind=image\|audio`                   | 管理员上传实际格式校验                        |
| `GET /api/media/:id`                                  | 图片、缩略图与 Range 音频；未发布素材限管理员 |
| `GET /api/state`、`GET /api/admin/status`             | 会话及初始化状态                              |
| `POST /api/setup`                                     | 使用服务器初始化令牌创建唯一管理员            |
| `/api/auth/sign-in/email`、`/api/auth/sign-out`       | 登录、退出                                    |
| `GET /api/stats`、`POST /api/visits`                  | 签名匿名身份和真实统计                        |
| `POST /api/checkin`、`POST /api/likes`                | 幂等签到和点赞状态                            |
| `POST /api/messages`                                  | 提交私人留言；输入校验、限流和重试去重        |
| `GET /api/messages?page=1`                            | 管理员分页查看留言                            |
| `PATCH /api/messages/:id`、`DELETE /api/messages/:id` | 管理员标记已读或删除                          |
| `GET /api/weather`                                    | 已保存地点的 Open-Meteo 天气缓存              |
| `GET /api/locations?q=城市`                           | 管理员搜索城市、时区和天气坐标                |
| `POST /api/weather/preview`                           | 管理员预览草稿地点的天气，不修改公开设置      |

## 反向代理与限流

当 `APP_URL` 使用 HTTPS 时，启动入口设置 `trust proxy = 1`，适用于 Railway 边缘代理到应用的一跳转发；本地 HTTP 默认不信任转发头。使用其他部署方式或多层代理时，应按实际代理链调整 `server/index.ts` 并验证限流中的客户端 IP，不要直接信任所有转发头。[Express 说明](https://expressjs.com/en/guide/behind-proxies.html)。
